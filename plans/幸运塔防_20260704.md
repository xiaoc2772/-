## 0. 目标与定位

- 在 `/games/lucky-td` 上线一款**单人闯关制塔防**，游玩可获得积分（遵守系统每日积分上限）。
- 玩法融合两个参考来源：
  - **无聊塔防**：固定时间步长的确定性模拟、seed + 操作日志回放校验、波次/路径/经济框架、Canvas 分层渲染、计分公式思路。
  - **明日方舟**：部署费用自动回复、干员职业分工、阻挡机制（近战单位站在路径上挡怪并承伤）、撤退/再部署、部署上限、基地生命。
- 平台特色「幸运」机制：波次间 3 选 1 幸运祝福、稀有幸运金币怪，提供局内变化与品牌记忆点（全部由 seed 决定，保持可回放）。
- 反作弊口径与现有游戏一致：**服务端不信任客户端**，提交后由 Go 引擎完整重放对局并计算权威分数。

### 非目标（v1 不做）

- 多人对战、异步排行对抗、观战/回放分享。
- 干员养成/抽卡解锁（v2 可与卡牌系统联动）、皮肤、体力系统。
- 音效音乐包（v1 至多保留轻量程序化音效开关）。
- 明日方舟式朝向/异形攻击范围（v1 用圆形射程，见待确认项）。
- 地图编辑器、运营后台配置界面（数值走仓库内配置文件）。

## 1. 参考来源要点与取舍

### 1.1 取自无聊塔防（技术骨架）

| 采纳 | 说明 |
| --- | --- |
| 固定时间步长游戏循环 | 逻辑固定频率推进，渲染帧率解耦；本项目定为 **30Hz 逻辑帧**（降低服务端重放成本） |
| 确定性 seeded RNG + 操作日志回放 | 与平台「seed + moves 服务端复算」反作弊模式天然契合 |
| 瓦片网格 + 线段路径地图 | 地图 = 网格 + 路径点序列 + 可部署位标记 |
| 波次体系与 HP 成长曲线 | 分段指数成长，Boss 收尾 |
| 计分思路 | 波次分 + 基地存活分（+ 幸运加成），弃用其速度分与回放版本协议 |
| Canvas 分层渲染 | 静态背景层 / 动态实体层 /（可选）特效层 |
| 性能手段 | 距离平方比较、对象数组原地紧凑化、UI 降频刷新、移动端特效降档 |

**明确不采纳**：22 种塔的体量（v1 收敛到 8 个单位）、塔内 5 级升级树、士兵/坦克 AI 单位、程序化 Web Audio 音效全家桶、单文件组织方式。

### 1.2 取自明日方舟（玩法灵魂）

| 采纳 | v1 简化方式 |
| --- | --- |
| 部署费用（cost）自动回复 | 初始 10 费，每秒 +1，上限 99；先锋击杀回费 |
| 职业分工 | 收敛为 5 类：先锋 / 近卫 / 重装 / 狙击·术师（远程）/ 医疗 + 1 个辅助特色位 |
| 阻挡机制 | 近战单位部署在路径格，阻挡 1~3 个敌人；被阻挡敌人停下攻击该单位；单位有 HP，可被击杀 |
| 高台/地面位 | 地图格子分「近战位」（路径上）与「远程位」（路径旁），职业限定可部署位类型 |
| 撤退与再部署 | 撤退返还 50% 费用，进入独立再部署冷却（20~40s） |
| 部署上限 | 场上同时最多 6 个单位 |
| 基地生命 | 10 点；敌人进终点扣 1（Boss 扣 3），归零判负 |
| 双伤害类型 | 物理（吃防御 DEF）/ 法术（吃法抗 RES），数值全部配置化 |
| 技能 | v1 仅**自动触发**技能（攻击充能，满自动放），不做手动开技能 |

**明确不采纳（v1）**：朝向与方向性攻击范围、干员精英化/潜能、地形机关（热泵/结冰）、隐匿/飞行单位（飞行留 v2）、手动技能。

## 2. 玩法定稿（v1 数值框架）

以下数值全部进入配置文件（见 4.2），M4 平衡性调整只改配置不改代码。

### 2.1 核心循环

```
进入页面 → 查看状态（冷却/今日积分/历史战绩）
  → 选择地图（v1 两张）→ 确认出战编队（v1 固定 8 人全可用，选 ≤6 上场）
  → 开始（服务端建会话，下发 seed）
  → 战斗：费用回复 → 部署/撤退 → 敌人沿路径进攻 → 波次推进
      → 每 5 波：幸运祝福 3 选 1
      → 每波结束：checkpoint 增量上报操作日志 + 状态哈希（会话滑动续期）
  → 通关 / 基地摧毁 / 主动结算 → submit
  → 服务端重放全部操作日志 → 权威分数 → 按每日上限发积分
  → 结算弹窗（分数拆解、获得积分、冷却倒计时）→ 记录写入历史
```

| 磐石重盾 | 重装 | 近战位 | 16 | 3 | 物理单体（低） | 技能：充能满后 5s 内防御翻倍 |
| 双刃游侠 | 近卫 | 近战位 | 12 | 2 | 物理单体（高） | 技能：三连斩（3 倍攻） |
| 烈焰剑士 | 近卫 | 近战位 | 14 | 1 | 物理溅射 | 攻击对阻挡目标周围小范围溅射 50% |
| 鹰眼射手 | 狙击 | 远程位 | 10 | 0 | 物理单体 | 优先攻击「离终点最近」的敌人 |
| 星辉法师 | 术师 | 远程位 | 15 | 0 | 法术范围 | 小范围 AOE，克制高防 |
| 月光医师 | 医疗 | 远程位 | 12 | 0 | 治疗 | 持续治疗射程内 HP 最低友军 |

- 所有单位属性：HP / 攻击 / 攻击间隔（逻辑帧）/ 射程（milli-tile）/ DEF / RES / 阻挡数 / 技能充能。
- v1 无局内升级：深度来自部署时机、站位与费用管理（明日方舟式），而非升级树（无聊塔防式）。

### 2.3 敌人（5 常规 + 1 特殊）

| 敌人 | HP 倍率 | 速度 | DEF/RES | 特点 |
| --- | --- | --- | --- | --- |
| 碎星杂兵 | ×1.0 | ×1.0 | 低/低 | 基准单位 |
| 疾影狼 | ×0.7 | ×2.0 | 低/低 | 快速，考验封路 |
| 重甲卫 | ×2.5 | ×0.6 | 高/低 | 克制物理，需要法师 |
| 咒盾傀儡 | ×1.6 | ×0.8 | 低/高 | 克制法术，需要物理 |
| 深渊魔王（Boss） | ×25 | ×0.5 | 中/中 | 第 15 波登场，进终点扣 3 生命 |
| 幸运金币怪（特殊） | ×1.2 | ×1.4 | 低/低 | seed 决定的稀有出现，击杀 +固定幸运分 |

- 波次 HP 成长（草案）：`HP(w) = base × 1.16^w`，第 11 波起改用 `×1.10^`（分段放缓），Boss 独立倍率；由 M4 平衡回调。
- 击杀奖励：v1 不设独立金币，经济只有「费用」一种资源（先锋回费 + 每波结束 +3 费）。

### 2.4 幸运祝福（3 选 1，第 5/10 波结束后触发）

从祝福池（seed 抽 3 项）中选 1，例：费用回复 +25%、全体近战 HP +20%、远程攻击 +12%、基地生命 +2、下一波敌人 HP -10%、立即 +12 费用。选择本身是一条操作日志（`bless` action），保持可回放。

### 2.5 地图（v1 两张，横屏网格）

| 地图 | 网格 | 路径 | 波次 | 倍率 |
| --- | --- | --- | --- | --- |
| 新手草原 | 12 列 × 7 行 | 单路径 S 形（右进左出） | 15 | HP ×1.0 |
| 双径峡谷 | 13 列 × 7 行 | 双路径汇流（右侧双口进，左出） | 15 | HP ×1.15，分数 ×1.2 |

进攻方向约定：**敌人从右缘刷入，基地在左缘**（美术朝向据此定：我方朝右、敌人朝左，路径回折时渲染器镜像）。

地图数据 = 网格尺寸 + 路径点序列（每条路径）+ 近战位/远程位格子清单 + 波次表（`{帧偏移, 敌人类型, 路径序号, 数量, 间隔帧}`）。

### 2.6 计分与积分

```
波次分 = Σ 每波通过分（第 w 波 = 10 + 2w）
基地分 = 剩余生命 × 15
击杀分 = 击杀数 × 1
幸运分 = 金币怪 + 锦鲤等幸运来源
总分   = (波次分 + 基地分 + 击杀分 + 幸运分) × 地图分数倍率
```

- 目标量级：新手图通关约 **350~500 分**，中途失败按比例衰减；单局用时 8~12 分钟，积分收益率与现有游戏对齐（由 M4 校准）。
- 积分 = 服务端权威分数，经现有每日积分上限截断（超限仍可玩但不发分，提示口径与其他游戏一致）。
- 冷却：结算后 5s（沿用 `game_cooldowns` 平台惯例）。

## 3. 总体架构与关键决策

### 3.1 命名约定

| 位置 | 取值 | 参照先例 |
| --- | --- | --- |
| DB `game_type` | `lucky_td` | `whack_mole`、`game_2048` |
| API 路径 | `/api/games/lucky-td/*` | `/api/games/whack-mole/*` |
| 前端路由 | `/games/lucky-td` | 同上 |
| Go 包 | `backend/internal/luckytd` | `whackmole`、`game2048` |
| 前端引擎 | `src/lib/lucky-td/`（引擎体量大，建目录而非单文件） | `farm-v2/`、`cards/` 目录先例 |

### 3.2 核心决策：确定性双引擎 + 服务端全量重放

**决策**：模拟核心用「引擎规格 + 双实现」——TS 引擎驱动客户端实时游玩，Go 引擎在 submit 时以最快速度重放操作日志得到权威结果。

**理由**：
- 平台 7 个现有游戏全部服务端权威/服务端复算，积分可兑换直充额度，作弊有真实成本，不能采用「客户端上报分数」。
- 塔防实时性强，roguelite/2048 式「每步走服务端」不可行（每秒 30 逻辑帧）。
- 无聊塔防已证明单语言确定性回放可行；跨语言的关键风险是浮点数，用**纯整数运算**消除（见 4.1）。
- 平台已有跨语言 RNG 先例：roguelite 前端用 `seedrandom`，Go 侧有对应移植 `backend/internal/roguelite/seedrandom.go`，直接复用该模式。

**成本评估**：15 波 ≈ 30Hz × ~10min ≈ 1.8 万逻辑帧，场上实体峰值 < 200，Go 重放为纯整数运算，单局重放预计 < 500ms；设帧数上限与超时兜底（见 6.3）。

**接受的残余风险**：确定性重放类游戏（match3/linkgame 同样存在）无法防「本地 TAS 式搜索最优操作」，属平台既有口径，接受。

### 3.3 请求与数据流

```
浏览器(TS 引擎实时模拟 + Canvas 渲染)
   │  status/start/checkpoint/submit/cancel
   ▼
Caddy Gateway ── 精确路径 /api/games/lucky-td/* ──▶ Go API (luckytd handlers)
                                                     │
                                        ┌────────────┼──────────────┐
                                        ▼            ▼              ▼
                                  game_sessions  Go 重放引擎    economy(积分/每日上限)
                                  game_records   (submit 时)   game_daily_stats
                                  game_cooldowns                point_ledger
```

## 4. Part 1：框架

> 目标：产出「一份规格、两份实现、一套一致性护栏」。本部分完成前，前后端不进入实体开发。

### 4.1 确定性模拟规格（`docs/lucky-td-engine-spec.md`）

需要成文的硬性规则：

1. **时间**：逻辑帧 30Hz；所有时长以帧为单位（攻击间隔、技能充能、再部署冷却）。渲染插值与倍速（1×/2×）只改变现实时间与逻辑帧的映射，**不进入逻辑层**。
2. **数值**：逻辑层**禁止浮点**。
   - 坐标/射程：milli-tile 整数（1 格 = 1000）；沿路径移动用「累计毫格进度」表示。
   - 百分比加成：万分比整数（+15% = 1500），先乘后除、统一舍入方向（向下取整），文档规定每个公式的运算顺序。
   - 距离判定：平方比较，不开方。
3. **随机**：单一 32 位整数 RNG（复用 roguelite 的 seedrandom 移植模式），**逻辑 RNG 与视觉 RNG 分离**（视觉抖动、粒子不消耗逻辑 RNG）——无聊塔防同款设计。
4. **顺序**：实体按稳定 ID 升序遍历；目标选取的平局裁决规则成文（先比路径进度，再比 ID）；Go 侧禁止依赖 map 遍历顺序。
5. **操作日志**：`{frame, seq, type, payload}`；type ∈ `deploy / retreat / bless`；同帧多操作按 seq 排序。倍速/暂停不记日志。
6. **状态哈希**：每波结束对规范化状态（实体列表、费用、生命、RNG 状态）做 FNV-1a 哈希；客户端随 checkpoint 上报，服务端重放后比对——既是反作弊证据，也是双引擎失同步的报警器。
7. **引擎输入输出**：`init(seed, mapId, squad)` → `state`；`tick(state)` → `state`；`applyAction(state, action)` → `state | error`；`finalize(state)` → `result`。纯函数式接口，两端签名一致。

### 4.2 数据驱动配置（单一来源）

- 位置：`src/lib/lucky-td/config/lucky-td-config.json`（单位/敌人/地图/波次/祝福/计分/上限全部在内）。
- TS 直接 import；Go 用 `//go:embed` 嵌入同一份文件（构建时从前端目录复制到 `backend/internal/luckytd/config/`，加校验脚本保证两份文件字节一致）。
- 配置带 `version` 字段，写入会话 payload；重放时用会话记录的版本对应的配置（v1 简化：配置变更时使旧会话直接过期作废，成文即可）。

### 4.3 会话协议与 API 契约

沿用平台统一响应包（`{ success, data, message }`）与 Cookie 会话认证。

| 端点 | 方法 | 请求 | 响应要点 |
| --- | --- | --- | --- |
| `/api/games/lucky-td/status` | GET | - | 余额、今日统计、冷却、每日上限、最近战绩、活跃会话（含已上报日志，供恢复） |
| `/api/games/lucky-td/start` | POST | `{mapId, squad[]}` | 校验编队合法/无活跃会话/冷却，建会话下发 `sessionId, seed` |
| `/api/games/lucky-td/checkpoint` | POST | `{sessionId, waveIndex, actionsDelta[], frame, stateHash}` | 追加日志、滑动续期会话（2048 先例）、记录服务端到达时间（配速审计用） |
| `/api/games/lucky-td/submit` | POST | `{sessionId, actionsDelta[], finalFrame, claimedScore}` | Go 全量重放 → 权威分数 → 发积分 → 写 `game_records`，幂等 |
| `/api/games/lucky-td/cancel` | POST | `{sessionId}` | 放弃会话，无积分 |

- 会话存 `game_sessions`（payload JSONB：seed、mapId、squad、累计操作日志、各波 checkpoint 哈希与服务端时间戳、配置版本）。**无需新增数据库迁移**。
- 会话 TTL 2h + checkpoint 滑动续期；上限护栏：总帧数 ≤ 54,000（30 分钟）、操作数 ≤ 600、checkpoint 次数 ≤ 20。
- 断线恢复（should-have）：status 返回活跃会话的 seed + 全量日志，客户端本地以最大速度重模拟至断点继续玩；v1 若延期则活跃会话只支持「放弃重开」。

### 4.4 跨语言一致性护栏（本部分的验收核心）

1. **黄金回放向量**：`src/lib/lucky-td/__fixtures__/golden/*.json` —— 每条含 `{seed, mapId, squad, actions[], 期望每波哈希, 期望最终结果}`。TS 侧 Vitest 与 Go 侧 `go test` 消费**同一批文件**，双端结果必须全等。覆盖：空过局、满编通关局、中途败北局、含全部祝福分支局、金币怪出现局、边界（费用恰好不足、阻挡满、同帧多操作）。
2. **模糊一致性测试**：脚本随机生成 200+ 局随机操作序列，跑双端比对哈希（CI 可选，本地必跑）。
3. **失同步遥测**：生产中 submit 重放哈希与 checkpoint 哈希不一致时，记录结构化日志（区分「作弊嫌疑」与「引擎失同步」需人工判读），不静默吞错。

### 5.2 服务层要点（照抄平台既有形制，重点列差异）

- 事务模式：`withRetryableTx` + `ensureUser` + `lockUserAccount`（防并发双开），与 roguelite `service.go` 一致。
- 复用表：`game_sessions` / `game_records` / `game_cooldowns` / `game_daily_stats`；积分走 economy 现有「每日上限内原子发放」路径，入 `point_ledger`。**预计零新增迁移**；若最终战绩需要塔防专属字段，优先塞 `game_records` 既有 JSON 字段，实在不够再开 `00xx_lucky_td.sql`。
- **checkpoint 是新形态**（2048 只有单次滑动续期，本游戏是多次增量日志）：
  - 校验：会话属于本人、状态 playing、waveIndex 单调递增、帧数单调递增、操作数/帧数不超上限。
  - 记录 `serverReceivedAt`，供 submit 时配速审计。
- **submit 安全清单**：
  - 幂等：同 session 重复提交返回首次结果（record 以 sessionId 关联，roguelite 同款）。
  - 全量重放：`claimedScore` 仅作日志对照，**发分只认重放结果**。
  - 配速审计：`现实耗时 ≥ 总帧数/30 ÷ 最大倍速(2) − 容差`，且各 checkpoint 服务端到达时间与其帧数一致——封死「本地光速模拟后直接交卷」。
  - 重放超时保护（context timeout 3s），超时按失败处理并告警，不发分。
  - 最短对局时长（如 ≥ 30s）与结算冷却 5s。
- 速率限制：接入 `httpserver/rate_limit.go` 现有机制（checkpoint 频率 ≤ 1 次/5s 量级）。

## 6. Part 3：前端（美术 / 动画 / 界面）

> 前置依赖：Part 1 的 TS 引擎与配置。渲染层可先用占位美术开发。

### 6.1 页面与渲染架构

```
src/app/games/lucky-td/
├── page.tsx                    # 页面壳：状态屏 / 战斗屏 / 结算弹窗的编排与 API 对接
├── _components/                # BattleCanvas、DeployTray、CostBar、WaveBanner、
│                               # BlessingPicker、SquadPicker、ResultModal、RecordsList
└── _styles/lucky-td.css        # 沿用现有游戏「页面私有 css」惯例

src/lib/lucky-td/
├── engine/                     # Part 1 交付（纯逻辑）
├── renderer/                   # Canvas 渲染器（与 React 解耦，requestAnimationFrame 驱动）
└── config/
```

- **React 只管 HUD 与弹窗，Canvas 只管战场**：游戏循环、实体渲染在 renderer 内部用可变状态跑（这是性能豁免区，遵循无聊塔防模式）；每 6 逻辑帧向 React 同步一次 HUD 快照（费用/生命/波次/技能充能），避免 30Hz setState。
- 双层 Canvas：`bgCanvas`（网格 + 路径 + 部署位标记，仅地图变更/resize 重绘）+ `mainCanvas`（单位/敌人/弹道/飘字/粒子）。粒子预算内不单开第三层。
- 渲染插值：逻辑 30Hz、渲染跟随 rAF，实体位置在两逻辑帧间线性插值，保证 60/120Hz 屏幕下移动平滑。
- 适配：**横屏舞台**（逻辑舞台 1280×720，16:9，整体等比缩放适配容器，DPR 感知）；桌面端居中限宽。移动端进入战斗时尝试全屏 + `screen.orientation.lock('landscape')`（Android Chrome 可用；iOS 不支持则显示「请横屏游玩」引导浮层，检测 `orientation` 变化自动进入）。入口/状态屏保持竖屏可正常浏览，仅战斗屏要求横屏。倍速 1×/2× 与暂停按钮（只影响现实时间映射）。

### 6.2 美术方向与资源清单

- 风格：延续平台小游戏的**明快卡通 + 描边贴纸感**（对齐 roguelite/2048 现有封面气质），原创设计，规避明日方舟视觉元素。
- 资源全部走 `public/images-optimized/ui/games/` 现有管线（webp）：

| 资源 | 交付规格 | 数量 |
| --- | --- | --- |
| 游戏中心卡片 `covers/lucky-td.webp` + `mascots/lucky-td.webp` | 对齐现有卡片尺寸 | 2 |
| 单位战场精灵（托盘/编队复用同图，无需单独头像） | 256×256 webp 透明 | 8 |
| 敌人战场精灵（含 Boss 320×320） | 256×256 webp 透明 | 6 |
| 地图装饰背景（可选，垫在棋盘下方） | ≤1280 宽 webp | 2 |

- 棋盘/地块/出怪口/基地门/弹道/特效**全部程序化绘制**（无素材）；功能图标用 `lucide-react` + Emoji（平台惯例）。必需生成图仅 **16 张**。
- **动画策略（已确认：程序化动画）**：v1 不做逐帧序列图。战场动画 = 静态精灵 + 程序化变换（呼吸、闪白、顶身、压扁回弹、消散）+ 粒子/飘字。**逐动画参数表、生图操作流程与全部提示词见 `docs/lucky-td-art-guide.md`**，该文档同时是 M3 渲染器的实现规格。
- 美术兜底：若素材延期，renderer 内置「几何占位皮肤」（色块 + 图标），保证联调不被美术阻塞。

### 6.3 界面与交互（逐屏）

1. **入口/状态屏**（对齐 2048/roguelite 页面形制）：规则说明、今日积分进度与上限提示、冷却倒计时（本地倒计时，沿用 2048 刚改的模式）、最近战绩列表、地图选择、编队（8 选 ≤6，带职业/费用/阻挡展示）、开始按钮。
2. **战斗屏**：
   - 顶栏：波次 x/15、基地生命、倍速、暂停、结算/放弃。
   - 底部部署托盘：6 张出战单位卡（费用、再部署冷却遮罩、费用不足置灰）。
   - **部署交互（移动端优先）**：点卡片 → 合法格高亮（近战位/远程位区分色）→ 点格子落位 → 显示射程圈确认；点场上单位 → 弹出「撤退」与技能充能状态。拖拽部署作为增强项排后。
   - 波次间幸运祝福 3 选 1 卡片弹层。
   - 反馈：伤害/治疗飘字、击杀音效开关（可选）、金币怪进场提示。
3. **结算弹窗**：分数拆解（波次/基地/击杀/幸运）、获得积分与今日进度、冷却倒计时、再来一局/返回。复用平台 ResultModal 形制。
4. **异常态**：会话过期、网络失败重试、恢复进行中会话的引导（若断线恢复落地）、`prefers-reduced-motion` 降级（关粒子与插值抖动）。

### 6.4 性能预算（移动端中端机）

| 指标 | 预算 |

| 实体峰值 | 敌人 ≤ 60、弹道 ≤ 80、粒子 ≤ 150（超限丢弃最旧粒子） |

| 主包增量 | 引擎 + 渲染器 gzip ≤ 60KB（不含图片；页面路由级代码分割，不进全站首包） |
| 图片总量 | webp 合计 ≤ 600KB，懒加载 |
